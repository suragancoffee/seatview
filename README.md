# 내 자리 미리보기 · 올림픽공원 공연장

**▶ 바로 보기: https://suragancoffee.github.io/seatview/**

한국체육산업개발(주) 공공데이터 활용 경진대회 출품용 웹 데모.
예매 전에 좌석을 고르면, 그 자리 눈높이에서 무대가 어떻게 보이는지 3D(또는 2D 추정)로 보여준다.

- 사용 공공데이터
  - 「한국체육산업개발주식회사_올림픽공원 공연장 실감형 콘텐츠」(공공데이터포털, GLB/DAE 3D 모델) + 각 공연장 대관 페이지의 좌석배치도·평면도·무대설치구간 도면
  - 「영문 공연정보」(공공데이터포털 파일데이터 15149169, CSV) — 최근 공연 목록과 예매 링크
  - 「한국문화정보원_공연정보」(공공데이터포털 3037877, Open API) — 공연장별 지난 공연 기록(2010~2024년, 2,502건)
- 화면 언어: 한국어 / English (오른쪽 위 버튼, 브라우저 언어에 따라 자동 선택)
- 기술: 순수 HTML + ES 모듈 + Three.js r170 (빌드 도구 없음, 서버 코드 없음)

## 실행 방법

```bash
# 저장소 폴더에서
python3 -m http.server 8000
# 브라우저에서 http://localhost:8000  (주소 끝에 #kspo, #hb, #lake, #g88, #oh, #muse 로 바로 이동 가능)
# 특정 좌석: #kspo&stage=end1&zone=8&depth=front  · 휠체어석: &wc=w8  · 시선: &y=20&p=-5&f=30
```

`file://` 로 열면 fetch/모듈이 막혀 동작하지 않는다. 반드시 로컬 서버로 연다.

## 3D 모델 처리 과정

원본은 공공데이터포털/기관 홈페이지의 GLB(우리금융아트홀, 티켓링크 라이브 아레나, 수변무대, 88잔디마당)와 DAE(KSPO DOME).
`@gltf-transform/cli` 로 다음 순서로 처리했다.

1. (KSPO DOME만) COLLADA2GLTF로 DAE → GLB 변환. 원본이 부품 10만 개·재질 10만 개로 쪼개져 있어 `dedup → flatten → join` 으로 7개로 정리
2. `weld` → `simplify`(ratio 0.3~0.4, `--lock-border`) → 텍스처 1024px `resize` → `webp` → `meshopt` 압축
3. 야외 모델은 `KHR_materials_pbrSpecularGlossiness` 를 `metalrough` 로 변환

| 공연장 | 원본 | 웹용 |
|---|---|---|
| 우리금융아트홀 | 170.2MB (GLB) | 12.1MB |
| KSPO DOME | 475.6MB (DAE) | 15.7MB |
| 티켓링크 라이브 아레나 | 79.0MB (GLB) | 8.3MB |
| 수변무대 | 24.7MB (GLB) | 8.5MB |
| 88잔디마당 | 10.9MB (GLB) | 5.7MB |

용량 단위는 모두 10진 MB(1MB = 1,000,000바이트)로 통일했다.

처음에 simplify를 너무 강하게(0.12) 걸었을 때 무대에 대각선 면이 생기는 오류가 있어, 원본과 같은 시점 렌더를 나란히 비교해 강도를 정했다.

모델은 `models/` 폴더에 `.glb`로 들어 있다. (Claude 아티팩트 데모판은 호스팅이 `.glb` 확장자를 받지 않아 base64 텍스트로 넣었지만, 이 저장소는 원래 형식을 쓴다.)

## 좌석 링크 공유

「이 자리 링크 복사」 버튼은 지금 공연장·좌석·무대 배치·휠체어석·시선 방향(y=좌우 각, p=상하 각, f=확대 시야각)을 주소 뒤(`#`)에 담아 복사한다. 좌석을 바꿀 때마다 주소도 바뀌어 새로고침해도 같은 자리가 열린다. 주소의 값이 실제로 없는 좌석이면 그 공연장 기본 좌석으로 연다. 서버에 아무것도 저장하지 않는다.

## 휠체어석

각 공연장 좌석배치도의 장애인석 표시를 옮겼다. 눈높이는 휠체어에 앉은 기준 1.25m.

| 공연장 | 위치(좌석배치도 기준) |
|---|---|
| 우리금융아트홀 | 1층 A·C구역 22열 뒤 12석 (바닥 높이는 모델에서 측정) |
| KSPO DOME | 5~11구역 뒤 장애인석 라인(1층 맨 뒤 통로, 모델에서 바닥 4.75m 측정) — 3곳 |
| 티켓링크 라이브 아레나 | 2층 남측(남서·남동) 20석. 콘서트(남측 무대)에서는 무대 뒤라 경고 표시 |
| 올림픽홀 | 22석: F1·F2·F3구역 맨 앞 줄 앞, B1·D1구역 무대 쪽 끝 |
| 뮤즈라이브 | 7열 끝 3곳 |
| 수변무대·88잔디마당 | 도면에 정보 없음(안내 문구만 표시) |

KSPO DOME은 무대 배치에 따라 휠체어석이 무대 정면/측면/뒤가 되므로 그에 맞는 경고를 띄운다.

## 공연으로 찾기 (공연 일정 연동)

영문 공연정보에는 최신 공연(2025~2026)이 있지만 **공연장 칸이 없고**, 국문 공연정보 API에는 공연장이 있지만 **2024년까지만** 들어 있다. 그래서 두 데이터를 이어 붙인다.

1. 공연 제목에 공연장 이름이 있으면(예: `… in KSPO DOME`) → **공연장 확인됨**
2. 없으면 제목 앞부분의 아티스트명(첫 두 단어, 숫자·서수·흔한 단어 제외)으로 국문 기록을 찾아, 그 아티스트가 가장 많이 공연한 곳을 고름 → **지난 공연 기준 추정 (n/전체)**. 근거가 1건뿐이면 확정하지 않고 후보로만 표시
3. 그래도 모르면 → **공연장 미확인**, 사용자가 공연장을 직접 고름

현재 157개 공연 중 공연장 확인·추정 약 40%. 오매칭을 막으려고 `SUPER`, `GRAND`, `JAZZ` 같은 흔한 첫 단어는 두 번째 단어까지 같아야 인정한다.

### 자동 갱신

`.github/workflows/update-events.yml` 이 매달 2일에 `scripts/update-events.mjs` 를 돌려 `data/events.json` 이 바뀌었으면 커밋한다. Actions 탭 → 「공연 목록 갱신」 → Run workflow 로 바로 돌릴 수도 있다.

- 국문 공연정보 API 키는 **저장소 Settings → Secrets and variables → Actions → `KCISA_KEY`** 에만 넣는다. 코드·커밋에는 넣지 않는다.
- 영문 CSV는 EUC-KR 인코딩이라 그에 맞게 읽는다. 공공데이터포털이 보안문자를 요구하면 우회하지 않고 그달 갱신을 건너뛴다.
- 받아온 공연이 20개 미만이면 데이터 형식이 바뀐 것으로 보고 기존 파일을 유지한다.

## 좌표·매핑 방식 요약

- **우리금융아트홀**: 모델 안의 의자 재질(`PDM_TheaterSeat_*`) 정점 약 235만 개를 추출해 실제 좌석 위치를 구함. 0.45m 격자로 좌석 단위를 묶고, 계단식 열은 단차 높이로, 평평한 1~4열은 객석 원호 반지름(중심 x=-2.25, z=-4)으로 열 번호를 판정. 1층 22열·2층 8열과 구역별 시작 열(A구역 2열부터 등)이 좌석배치도와 일치. A·C구역 13~14열은 측면 날개 구간으로 앞열보다 무대 쪽에 있는 것이 실제 구조. (초기 버전은 열을 직선 보간해 A구역 14열이 통로 벽에 붙는 오류가 있었음)
- **KSPO DOME**: 좌석배치도는 모델 대비 90° 회전되어 있음(배치도 오른쪽 5~11구역 = 모델 -z). 장애인석 라인·박스석 등 비대칭 특징으로 방향 확인. 구역 라벨의 배치도 각도 → 모델 극좌표. **구역별 좌석 위치는 모델에서 색이 있는 의자 부품(좌판·등받이, 팔레트 색 중 채도가 있는 것)만 골라 구역 중심각 ±3° 부채꼴로 잘라 측정**: 실제 의자가 있는 거리 범위의 10%(앞쪽)·50%(가운데)·90%(뒤쪽) 지점, 높이는 의자 높이를 직선으로 맞춘 값(2층은 기울기 0.43 고정)에 앉은 눈높이를 더함. 1층은 23.5~44m로 구역 간 차이가 작고, 2층은 구역마다 달라(49구역은 52.5~57m) 예전 공통 공식(47.5~55.5m)으로는 일부 구역의 '앞쪽'이 의자 없는 곳에 놓였다. 처음엔 회색 부품까지 의자로 쳤다가 그것이 계단식 바닥(콘크리트 단)이라 의자 없는 곳에 시점이 생기는 오류가 있었고, 2층 맨 뒤 통로 너머의 짧은 줄은 앞이 난간에 가려 뒤쪽 시점을 56.8m까지로 제한했다. 52개 구역 × 앞·가운데·뒤 156개 시점을 모두 렌더링해 무대가 보이는지 확인. 측정 후에도 클릭 시 주변 5점 레이캐스트로 눈높이를 한 번 더 보정.
- **티켓링크 라이브 아레나**: 모델은 이동식 좌석이 접힌 상태(바닥 58.7×47.7m = 도면의 수납 시 59.6×48.3m와 일치). 도면의 인출 시 42.1×31.2m, 무대설치구간 30×18m(남측)를 기준으로 이동식 좌석 단과 무대를 절차적으로 생성. 동·서 정중앙은 출입구 부스라 해당 방향 시점을 ±13° 이동.
- **수변무대·88잔디마당**: 레이캐스트로 지형/계단석 높이 측정. 88잔디마당 특설무대는 예시 배치, 눈높이는 돗자리 착석(0.9m).
- **올림픽홀(2D)**: 평면도 그리드(6m=41px @70dpi)로 축척을 잡아 구역별 앞열/뒷열 위치(x, 무대까지 거리 d, 눈높이 h)를 추정. 좌석배치도는 비율이 맞지 않는 모식도라 클릭용 지도로만 사용.
- **뮤즈라이브(2D)**: 좌석배치도를 좌석 단위로 재현(237석 = 고정 198 + A·B열 간이 39). 좌석 폭 0.5m, 열 간격 0.92m, 단차 0.2m 가정.

## 좌석 수 참고

- KSPO DOME 14,151석 = 52개 구역 합계 13,948석 + 휠체어석 82석 + BOX석 121석 (좌석배치도 표 기준)
- 뮤즈라이브 237석 = 고정석 198석 + A·B열 간이석 39석

## 통계 카드 계산

- 무대 앞까지 거리: 눈 위치에서 **무대 앞선(선분)까지의 최단 수평거리**. 무대 폭 — 우리금융아트홀 20m, KSPO 엔드무대 26m, 티켓링크 콘서트 30m, 올림픽홀 18m, 뮤즈라이브 11m. 원형(센터) 무대는 가장자리까지, 핸드볼 모드는 코트 중앙까지
- 시선 각도: 출연자 머리 높이(무대 바닥 + 1.6m) 대비 상하각
- 출연자가 보이는 크기: 키 175cm 인물의 시야각 → 크게(>6°) / 적당히(>3.5°) / 작게(>1.6°) / 스크린 필요
- 무대 뒤·측면 경고: 아레나형은 무대 방향과 좌석 방향의 각도 차이로 판정

## 알려진 한계 / 개선 여지

- 영문 공연정보의 날짜는 데이터에 기록된 날짜이며 실제 공연일과 다를 수 있음(같은 날짜가 여러 건). 공연장 추정은 지난 기록 기반이라 틀릴 수 있어 화면에 근거를 함께 표시함

- 출연자 크기는 키 175cm 인물 1명 기준의 시야각 근사이며, 실제 공연의 LED 스크린·무대 연출은 반영하지 않음

- 좌석 위치는 열(또는 구역 내 앞/가운데/뒤) 단위 대표값(우리금융아트홀은 실제 의자 위치 추출값). 같은 열 안 좌석 번호별 차이는 미반영(뮤즈라이브 제외)
- 아레나형 공연장의 무대·LED 스크린은 예시 배치(실제 공연마다 다름)
- 올림픽홀 2층 높이, 뮤즈라이브 치수는 도면 치수 부재로 추정값
- 3D 모델은 메인 스레드에서 base64 디코딩 → 큰 모델은 저사양 기기에서 로딩이 느릴 수 있음
- 한 번 불러온 공연장 모델은 전환 속도를 위해 메모리에 유지함(5곳 모두 열면 GPU 메모리 사용 증가). 무대·좌석 소품은 다시 만들 때 이전 것을 해제함
- 레이캐스트는 BVH 없이 수행(클릭당 5회) → three-mesh-bvh 도입 시 개선 가능

## 변경 이력

- 좌석 링크 공유(주소에 좌석·시선 저장), 5개 공연장 휠체어석 표시, KSPO DOME 52개 구역 좌석 위치를 모델의 의자 정점에서 측정한 값으로 교체

- 공연으로 찾기(영문 공연정보 + 국문 공연정보 연동), 공연장별 지난 공연 수, 한/영 화면 전환, 공연 목록 월간 자동 갱신 추가

- 우리금융아트홀 좌석 좌표를 3D 모델의 실제 의자 위치에서 추출하도록 교체(측면 뒤쪽 열이 벽에 붙던 오류 수정)

- 외부 검토 반영: 무대 앞선 기준 거리 계산, 소품 재생성 시 GPU 자원 해제, 공연장별 로딩 Promise 캐시(빠른 전환 시 로딩 화면 오작동 방지), 핸드볼 모드 용어(코트 중앙·선수), 용량 단위 통일, KSPO 좌석 수 내역 명시
